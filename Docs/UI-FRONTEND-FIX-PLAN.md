# UI ↔ Chaincode Reconciliation — Fix Plan

**Sources:** `UI-CHAINCODE-RULES.md` (chaincode coffee v2.3, authoritative) and
`UI-PORTAL-INVENTORY.md` (frontend static inventory). Branch `features`, HEAD `434fbdda`.
**Rule of the fix:** where UI and chaincode disagree, the chaincode wins. Never invent a status
the chaincode never assigns; never show an action the current on-chain status does not allow;
never fake a result client-side when a real endpoint exists. Static findings only — every fix
must be verified with `npx tsc --noEmit` in `ui/` and `next build`, plus a browser render
against the live API (3001) afterwards.

## Tier 1 — correctness (fix where cheap, same pass)

- **ECX:** add Auto-Release button for `ASSIGNED` lots (`POST /ecx/lots/:lotId/auto-release`); Assign dialog must pick contracts from `GET /portals/ecx/active-contracts` (no free text); grade dialog must require a cupping score and must **not** block moisture >12% client-side (chaincode returns REJECTED — show the reason); fix mutating handlers to surface axios error bodies instead of "Request failed with status code 503".
- **Exporter:** Reports "Generate" button must work (or be removed); fix payment-settlement dialog math — exporter receives `amountETB − retainedETB`, not the retained portion; fix audit-stats effect to fire on tab 7, not 6; add LC document submission path (`POST /shipments/:shipmentId/lc-documents` needs a caller); shipment "has export permit" must use `GET /permits/exporter/:exporterId`, not an inspection-row heuristic.
- **Banks:** bulk approve needs real checkboxes + a "Bulk Approve" button; forex allocate must send the user-typed `approvalRef`/`officer` (route reads `officer`/`approvalRef`, not `nbeOfficer`/`nbeApprovalRef`); forex detail "Confirm" button must actually call an endpoint; add forex Reject (`POST /banking/forex/:forexID/reject`) and Utilise (`POST /forex/utilize`) actions; fix KPI branches (All LCs shows Payment Release KPIs); remove duplicate `bankingRoutes` mount in `server.ts` if confirmed duplicate.
- **Customs:** complete-inspection must allow a failed outcome (not hardcoded PASSED); wire the clearance dialog inputs that are `defaultValue`-only; open the Rejection Details dialog from rejected rows and show the stored reason; render the dead `CustomsInspection` / `CustomsClearedShipments` components or remove their imports; fix the permit/certificate gate to use fields the API returns (`GET /quality/inspections/by-shipment/:id` returns `certificationNumber`, no `exportPermitNo`).
- **NBE:** fix KPI/tab-index misalignment (KPIs shifted by one from tab 5; audit stats fire on tab 8 not 7; tab labels show wrong counts); SWIFT KPIs must count `SETTLED`, not `SENT`; unify the high-value threshold ($1,000,000) between portal and sub-component; "Review" on a `NBE_APPROVED` alert must not offer an approve that can only run on DRAFT; add repatriation penalty (`POST /repatriation/:id/penalty`) and waiver-approve (`POST /repatriation/:id/waiver/approve`) actions; make the compliance panel openable.
- **ECTA:** fix Approved/Rejected KPI cards (load all application statuses, not pending-only); fix Schedule date field name (`requestedDate`); fix audit KPI effect to fire on tab 8, not 6; remove the production debug `<Alert>`; make the phytosanitary dialog send the fields it collects; licence details must not hardcode `Status: 'ACTIVE'`; capital minima must come from one source (the registration schema) — do not show three different minima.
- **Shipping:** add a rejection-reason input to the approval dialog (Reject currently can never succeed); fix grid shortcuts that always fail client-side (Start Land Transport, Stuff Container — route them through the dialog or prefill required fields); verification dialog must filter declarations client-side by `shipmentId` (backend ignores that query param); exporter lookup must use `GET /users/by-exporter/:exporterId`; "Download Documents" must use an authenticated fetch, not `window.open` on a JSON endpoint; remove the fake "Generate QR Code" button (or implement a real QR); render/enforce the required-documents list in the approval dialog.
- **Cross-cutting:** replace every hardcoded `http://localhost:3001` with `API_BASE_URL` (`DocumentManagementPanel`, `BlockchainSignatureVerification`, `AnalyticsDashboard` export, raw fetches in Banks/ECTA); `BlockchainBadge` must either verify or be labelled as a display-only indicator; `workflowEnforcement.ts` gates must use chaincode status names (`FREIGHT_BOOKED`, `VESSEL_LOADED`, …) and `canCreateShipment` must require an LC in `FOREX_ALLOCATED` or later — and portals should actually import it.

## Out of scope for this pass (record, do not silently "fix")

- **ECTA export permit is Postgres-only**: `POST /quality/inspections/:id/issue-permit` has a `TODO`/`SKIP BLOCKCHAIN` and a null tx id, and the customs handoff is unimplemented. That is an **API** fix, not UI. UI must not claim on-chain issuance there.
- **Chaincode loopholes** (`RecordInspectionResults` re-opening APPROVED inspections, generic setters, `PickupShipment` skipping customs, `CreateAndIssueLC` with no checks): UI must guard these client-side (disable the action on terminal states) but must not invent chaincode statuses.
- **Applicant licence application flow** (public applicant submit + login + status check): no portal UI exists at all. Needs a new public page — separate task, flag to the user.
- **Banks "Issue LC" (0.3)**: if the investigation shows no legitimate bank-side path, the fix is UI removal, not an API role widening.
- **Role-vocabulary mismatches** (display-name roles vs `requireRole` values): fix page gates to use the API's role values where the mismatch causes 403s; where the API itself accepts display names, leave it and note it. Do not change API RBAC semantics in this pass.
