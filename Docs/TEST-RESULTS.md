## 3. Real API bugs found (FAILs that are not Fabric/CouchDB)

These failed with the API running and are independent of the missing Fabric network. Ordered by severity.

1. **Exporter reject always 500s** — `POST /exporters/exporter-applications/:id/reject` → 500 `REJECTION_FAILED`. Server log: `TypeError: auditService.recordAudit is not a function` (`dist/routes/exporters.js:528`). The handler calls a method that does not exist on AuditService (it has `log()`, not `recordAudit()`). Consequence: no application can ever be rejected through the API, so the resubmit flow can never be reached by that path either.
2. **Applicant resubmit always 403s** — `POST /exporters/exporter-applications/:id/resubmit` as the applicant (valid applicant token, correct numeric id) → 403 FORBIDDEN. Root cause: `authMiddleware` rebuilds `req.user` from the decoded token but never copies `decoded.applicationId`, so the resubmit guard's applicant branch (`user.applicationId === params.applicationId`) can never pass. Only ECTA/ADMIN staff can resubmit. (Resubmit as ECTA → 200 PASS.)
3. **Post-delivery workflow is schema-broken** — `POST /post-delivery/:shipmentId/{payment,forex,lc-settlement,ecta-audit}` → 400 because `post_delivery_tracking` has no `payment_received` / `forex_repatriated` / `lc_settled` / `ecta_audit_completed` columns (the table has only tracking_id, shipment_id, arrival_date, warehouse_location, quality_recheck_status, status, notes).    - `PUT /quality/inspections/:id/approve` → 200 with a fabricated `certificateNumber` for an inspection that does not exist (0 rows in `quality_inspections`).

6. **Quality inspection create dies on CouchDB** — `POST /quality/inspections` → 500 `SERVER_ERROR: socket hang up` because the route writes to CouchDB first and CouchDB is not running. Unlike the shipment create (202, PG row, `blockchainSynced:false`), there is no degraded PG-only path, so no inspection can be created at all without CouchDB.
7. **NBE Repatriation tab has no backing route** — `GET /nbe/repatriation` → 404 Route not found. `nbe.ts` has no such GET (only GET /forex, POST approve, POST repatriation, GET /lc-monitoring).

9. **Customs routes take the `DECL-…` string id, not the numeric id** — `/customs/declarations/1/inspect` and `…/1/clear` → 404, while the same routes with `DECL-TMW977G36` → 200. Inconsistent with the exporter-application routes, which also take the APP-… string, while resubmit takes the numeric id — three different id conventions across the API.

## 7. Map corrections found during testing

Several paths in TEST-WORKFLOW-MAP.md do not match the code (retested with the real paths; both the wrong and right attempts are in §2):
- `POST /forex/confirm` → real: `POST /forex/:forexId/confirm`
- `POST /forex/allocate` requires `forexId` **and** `lcId`
- `POST /quality/inspections/:id/issue-certificate` → real: `POST /quality/issue`
- `POST /phytosanitary/{inspect,issue,revoke}` → real: `POST /phytosanitary/:certificateID/{inspect,issue}`, `/:certificateId/revoke`
- `POST /inspection/perform` → real: `POST /inspection/:id/results`
- Shipment lifecycle slugs → real: `/land-transport/start`, `/port/arrive`, `/container/stuff`, `/vessel/load`, `/vessel/depart`, `/destination/arrive`, `/delivery/complete`
- `POST /bordercrossing/<action>` → real: `POST /bordercrossing/:id/<action>`
- `POST /payments/:id/swift-initiate|swift-receive` → real: `POST /payments/:id/swift/initiate|swift/confirm`
- `POST /payments/repatriation/initiate` → real: `POST /payments/:paymentID/forex-repatriation`
- `POST /payments/:id/release` requires `exporterID` + numeric `amount`; `POST /payments/:id/forex-repatriation` requires `repatriationAmount`, `repatriationCurrency`, `exchangeRate`; `POST /customs/declaration/:id/reject` requires `rejectionReason`
- `POST /shipments/:id/book-freight` requires `freightForwarder`, `transportMode` (SEA/AIR), `estimatedDepartureDate`
- One customs declaration per shipment is enforced (`DECLARATION_EXISTS`).

## 8. Method & limits

- No repo source file was modified; nothing was committed or pushed. The API was not restarted. Test data (9 users, 3 applications, 2 shipments, 1 booking, 2 declarations, 1 rejected application) lives in the test Postgres DB and is namespaced with run id `TMW977G36`.
